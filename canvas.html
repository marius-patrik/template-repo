- Assign one canonical owner to each capability, data model and state transition. Refactor the owner rather than creating competing implementations.
- Prefer simple, cohesive, discoverable modules with descriptive names over generic `utils` or `misc` files.
- Separate core mechanisms from project- or provider-specific policies; configure differences instead of duplicating entire subsystems.
- Avoid unrequested compatibility shims, legacy fallbacks and transitional production paths. Delete obsolete implementations only after verifying their consumers and state.

- Preserve human approval gates; never bypass a review or required check merely to unblock a merge.
- Describe actual changes, verification and remaining gaps precisely in the pull request. Keep unrelated discoveries visible as separate tracked work.

## One source per kind of knowledge

### Decision

Four kinds of individually reviewable Markdown source records drive the four human-facing generated documents:

| Source records | Eligible status | Generated artifact |
| --- | --- | --- |
| `.agents/notes/*.md` | `published` | `.agents/README.md` |
| `.agents/requests/*.md` | `approved` | `.agents/PRD.md` |
| `.agents/decisions/*.md` | `accepted` | `.agents/ARCHITECTURE.md` |
| `.agents/rules/*.md` | `active` | `.agents/AGENTS.md` |

All selected records require YAML-style front matter containing `status`. Unpublished notes do not contribute to README; `.agents/TODO.md` is a separate, non-generated task file. Other source directories reject files without status rather than silently hiding them. Records assemble in lexical filename order with source backlinks relative to the generated document.

Derived Markdown is committed for review and GitHub rendering, but is not edited independently. A dependency-free Python generator writes it deterministically, and CI rejects stale outputs using normal GitHub Actions workflow discovery. Root `README.md` and `CONTRIBUTING.md` are Git symlinks to `.agents/README.md` and `.agents/AGENTS.md` respectively; `.agents/` and `.github/` themselves are real directories.

### Rationale

Separating the public project overview from normative requirements prevents the README from becoming an accidental competing PRD. Flat source folders avoid unnecessary nesting; clear ownership eliminates duplicated content and stale symlinks.

### Consequences

Edit records and regenerate the derived documents in the same change. Draft, rejected and superseded records remain in history but do not appear as current specifications. Public notes are not authoritative product requirements; requirements are owned by requests.

_Source: [0001-single-document-source.md](decisions/0001-single-document-source.md)_


## Native GitHub delivery and dual version modes

### Decision

`development` is the integration branch and `main` is the release branch. PRs into `main` must originate from this repository's `development`. All workflows are ordinary Git-tracked files under root `.github/workflows/`, making GitHub Actions discovery possible again.

`repo.versioning.mode` in root `repo.dfconfig` is one of `tags` (default) or `file`.

- **`tags` (default):** no `VERSION` file is tracked. On a push to `main`, the release workflow finds any SemVer tag already pointing at that commit, or calculates the next patch tag using the highest existing `vMAJOR.MINOR.PATCH` tag. It creates an immutable tag and a GitHub Release. Pull requests do not bump versions.
- **`file` (opt-in):** a `VERSION` file containing one strict `major.minor.patch` line is required. A same-repository PR gets exactly one automatic patch bump on its head (as in the previous file-driven release workflow); `main` releases must use that version. The proposed version must exceed all existing SemVer tags and may not reuse a tag on another commit.

The release workflow is serialized, idempotent against retry on the same commit, and never moves existing tags. Both modes require verifying the actual release and branch refs.

### Rationale

Tag-only mode avoids commits solely to update a version marker and prevents tag/file drift. Optional file mode supports projects that need a version visible in source, without imposing that requirement on templates.

### Consequences

Changing modes is an explicit source/configuration change. Switching to `file` requires adding `VERSION` with a non-colliding SemVer number; switching to `tags` removes it. PR workflow bumps occur only in `file` mode. Protect `main` in GitHub itself; the source-branch workflow is a supplemental guard.

_Source: [0002-development-and-release.md](decisions/0002-development-and-release.md)_


## Agent roles and portable skills

### Decision

`.agents/agents/` contains lightweight role profiles (orchestrator, planner, implementer, reviewer and verifier), one Markdown document per role. A role describes authority, inputs, expected output and the handoff; it does not clone global rules.

`.agents/skills/<name>/SKILL.md` contains reusable, task-triggered procedures with standard `name` and `description` front matter. Skills cover repository orientation, requirements, architectural decisions, implementation verification, independent review, documentation generation and release checks.

All roles inherit the binding constraints of generated `.agents/AGENTS.md`. Host runtimes may consume these files directly or map them into their own agent/skill registries; placing them here does not imply that a specific runner automatically loads them.

### Rationale

Separating roles from procedures enables composition and provider portability. A planner can use the requirements and architecture skills; a verifier can run implementation and release checks without sharing an implementer's incentives.

### Consequences

A project may add or remove roles and skills based on actual needs. Keep them small, verifiable and grounded in the repository; do not add speculative personalities, redundant rule copies or vendor-specific tooling requirements.

_Source: [0003-agent-roles-and-skills.md](decisions/0003-agent-roles-and-skills.md)_


## Native repository directories and a pinned DarkFactory submodule

### Decision

Root `.agents/` and `.github/` are independent physical Git directories, not symlinks. `.agents/` owns project documentation, source records, role instructions and portable skills. `.github/` owns native GitHub Actions workflows, scripts, PR templates and the **sole test directory** `.github/tests/`.

The root path `.darkfactory` is reserved exclusively for the pinned Git submodule `https://github.com/marius-patrik/DarkFactory.git`. It is a Git tree entry with mode `160000`, not a locally authored metadata directory. Project tests and GitHub workflows are not stored in the submodule.

### Rationale

GitHub workflow discovery requires an actual `.github/workflows/` tree. A symlinked `.github` broke CI dispatch, releases and automatic preservation of the `development` branch. Restoring native directories fixes the discovery contract. A submodule retains reusable DarkFactory code without conflating external and local repository ownership.

### Consequences

Do not put test files outside `.github/tests/`. Ensure all internal workflow/script paths use native root locations. Advance the pinned submodule commit explicitly and reviewably, and use `git submodule update --init --recursive` if local tooling needs its content.

_Source: [0004-single-darkfactory-root.md](decisions/0004-single-darkfactory-root.md)_


## Static repository Canvas and agent-owned interaction

### Decision

A single root `canvas.html` is generated from `git ls-files` and the local worktree. It is the **human view**, not a writable data source. Ordinary UTF-8 files are represented in full, while gitlinks, symlinks and binary files are described without dereferencing external sources. The renderer is deterministic and excludes its own output from source traversal.

The agent interface is implemented through repo-local procedures and tools in `.agents/`, not custom runtime JavaScript in HTML. A repository-specific context hook offers a compact turn snapshot; no automatic ChatGPT hook is assumed.

### Consequences

- Actual data must already exist in Git-tracked files before Canvas displays it. External facts and user reports require evidence-aware repository updates first.
- Generated-document projections stay derived from canonical notes, requests, decisions and rules, and the Canvas includes their checked-in projections.
- Source edits require Canvas regeneration and an automated check. The template retains no project-specific vehicle facts.
- The plugin manifest is opt-in for agent hosts that support its explicit command/skill/hook convention, not a generally installed ChatGPT connector.

# Native GitHub delivery and dual version modes

## Decision

`development` is the integration branch and `main` is the release branch. PRs into `main` must originate from this repository's `development`. All workflows are ordinary Git-tracked files under root `.github/workflows/`, making GitHub Actions discovery possible again.

`repo.versioning.mode` in root `repo.dfconfig` is one of `tags` (default) or `file`.

- **`tags` (default):** no `VERSION` file is tracked. On a push to `main`, the release workflow finds any SemVer tag already pointing at that commit, or calculates the next patch tag using the highest existing `vMAJOR.MINOR.PATCH` tag. It creates an immutable tag and a GitHub Release. Pull requests do not bump versions.
- **`file` (opt-in):** a `VERSION` file containing one strict `major.minor.patch` line is required. A same-repository PR gets exactly one automatic patch bump on its head (as in the previous file-driven release workflow); `main` releases must use that version. The proposed version must exceed all existing SemVer tags and may not reuse a tag on another commit.

The release workflow is serialized, idempotent against retry on the same commit, and never moves existing tags. Both modes require verifying the actual release and branch refs.

## Rationale

Tag-only mode avoids commits solely to update a version marker and prevents tag/file drift. Optional file mode supports projects that need a version visible in source, without imposing that requirement on templates.

## Consequences

Changing modes is an explicit source/configuration change. Switching to `file` requires adding `VERSION` with a non-colliding SemVer number; switching to `tags` removes it. PR workflow bumps occur only in `file` mode. Protect `main` in GitHub itself; the source-branch workflow is a supplemental guard.

Root `canvas.html` is the complete, deterministic and static human-readable view of Git-tracked repository content. def read_entry(root: Path, path: str, mode: str, sha: str) -> str:
    location = root / path
    if mode == "160000":
        return "Git submodule pinned commit: " + sha + "\n"
    if mode == "120000":
        return "Symbolic link to: " + os.readlink(location) + "\n"
    data = location.read_bytes()
    if b"\0" in data:
        return f"[Binary file; {len(data)} bytes; sha256 {hashlib.sha256(data).hexdigest()}]\n"
    try:
        return data.decode("utf-8")
    except UnicodeDecodeError:
        return f"[Non-UTF-8 file; {len(data)} bytes; sha256 {hashlib.sha256(data).hexdigest()}]\n"

# Canvas Web — repository application

The first-class Canvas UI is authored in `.github/app`. A deterministic build step reads
only allowlisted, Git-tracked repository documents and generates `src/generated/context.json`;
this derived file is not edited manually. GitHub Actions compile a React application into
`.canvas-dist/index.html` and `canvas.html`, publishing the former as the repository's
GitHub Pages site. No browser fetch, backend, credential, or independent authoritative
project state is required.

Stack: Bun, TypeScript, React, Rsbuild, Wouter (hash routes), Tailwind CSS v4, shadcn-style
Radix primitives, Motion, lucide-animated, React Flow + Dagre, and Dockview.

Local commands from `.github/app`:

```sh
bun install
bun run dev
bun run typecheck
bun run build
```

Site publishing requires the repository administrator to configure
**Settings → Pages → Source: GitHub Actions**. No workflow can bypass missing
GitHub Pages authorization or organization policy.

**Privacy:** GitHub Pages is a public deployment for this repo. The builder uses an
explicit allowlist and does not publish raw private archives, credentials or all
repository files. Reusing the app in a private repo must involve a separate security
review, not automatically opt in to public publishing.

The existing `.agents/tools/canvas.py` CLI is retained as the historical
source inspector/exporter while CI validates the React replacement. Both are derived
views; tracked authoring records remain authoritative.

## Prototype delivery

Pages builds on the feature branch deploy through the `canvas-preview` environment; after a reviewed release, main deploys through `github-pages`. Source input is compiled at build time and navigation remains local/read-only. The design/prototyping phase does not end automatically with a successful deployment.

## Current prototype controls

- The application title bar owns the global sidebar toggle, omnibar and Settings.
- The project route tree lives in the omnibar; the redundant secondary header was retired.
- Shortcuts are registered centrally with TanStack Hotkeys, defaulting to Mod+B (sidebar) and Mod+K (omnibar), and are editable in Settings. Custom bindings persist only in the current browser.
- Accent color selection uses react-colorful inside a Radix Popover and validates contrast using colord. The theme state remains local and independent of repository authority.

## Dockview application shell (v0.8)

Dockview now renders every route within one application-level compositor, replacing the
old nested Workbench instance and fixed page-switching layout. The title bar, omnibar,
navigation and status bar remain global. The workspace toolbar supports tab navigation,
splitting the active view, opening the graph and resetting the layout. Drag-and-drop
rearrangement, group splitting and panel closing are native Dockview interactions.

Wouter hash routes and Dockview tab selection are synchronized. Local layout preferences
are persisted under `canvas-dockview-layout-v1` and can be reset without changing
repository data. The build remains a static, read-only repository snapshot.

The Dockview compositor uses the official dockview-react panel API and keeps layout
state as UI-only local data; no authored repository file is modified through drag/drop.

Dockview layout acceptance is checked in Chromium before every Pages publication.

function KeybindingRow({ id }: { id: AppHotkeyId }) {
  const hotkey = useAppHotkeys()[id];
  const { setCustomHotkey, resetCustomHotkey, findConflicts } = useCustomHotkeys();
  const [error, setError] = useState("");
  const recorder = useHotkeyRecorder({
    maxSteps: 1,
    validate: (binding) => {
      const collisions = findConflicts(id, binding);
      return (
        collisions.length === 0 ||
        `Already assigned to ${collisions[0]?.meta?.name ?? "another command"}`
      );
    },
    onRecord: (binding) => {
      setError("");
      setCustomHotkey(id, binding);
    },
    onClear: () => {
      setError("");
      setCustomHotkey(id, null);
    },
    onReject: ({ message }) => setError(message),
    onCancel: () => setError(""),
  });

  return (
    <div className="keybind-row" data-command={id}>
      <div className="keybind-description">
        <strong>{hotkey.meta?.name ?? id}</strong>
        <small>{id}</small>
        {error && (
          <span className="keybind-error" role="alert">
            {error}
          </span>
        )}
      </div>
      <div className="keybind-controls">
        <kbd>{hotkey.hotkey ? formatForDisplay(hotkey.hotkey) : "Unassigned"}</kbd>
        <button
          type="button"
          className={`keybind-edit ${recorder.isRecording ? "recording" : ""}`}
          onClick={() => {
            setError("");
            if (recorder.isRecording) recorder.cancelRecording();
            else recorder.startRecording();
          }}
          aria-label={`Change shortcut for ${hotkey.meta?.name ?? id}`}
        >
          {recorder.isRecording ? "Press keys…" : "Edit"}
        </button>

          type="button"
          className="keybind-reset"

#!/usr/bin/env python3
"""Apply the declared native GitHub main-branch protection using the maintainer's gh login.

Requires GitHub CLI authenticated as a repository administrator.
Dry-run by default; pass --apply to mutate GitHub. Requires no saved PAT or extra secrets.
"""

from __future__ import annotations

import argparse
import json
import shutil
import subprocess
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
CONFIG = ROOT / "repo.dfconfig"
API_VERSION = "2026-03-10"


def declared_policy() -> tuple[str, str, dict]:
    """Read the canonical repository identity and exactly one main protection lane."""
    config = json.loads(CONFIG.read_text(encoding="utf-8"))["repo"]
    identity = config["identity"]
    repo = f'{identity["owner"]}/{identity["repo"]}'
    branch = identity["default_branch"]
    if branch != "main":
        raise ValueError(f"Refusing to protect unexpected default branch {branch!r}")
    lanes = [lane for lane in config["protection"]["lanes"] if lane["branch"] == branch]
    if len(lanes) != 1:
        raise ValueError("Expected exactly one declared protection lane for main")
    lane = lanes[0]
    checks = lane["required_checks"]
    if not isinstance(checks, list) or len(checks) < 2 or len(checks) != len(set(checks)):
        raise ValueError("Specify at least two unique required check names")
    payload = {
        "required_status_checks": {
            "strict": bool(lane["strict"]),
            "contexts": checks,
        },
        "enforce_admins": bool(lane["enforce_admins"]),
        "required_pull_request_reviews": {
            "required_approving_review_count": int(lane["approvals"]),
            "dismiss_stale_reviews": True,
            "require_code_owner_reviews": False,
        },
        "restrictions": None,
        "required_conversation_resolution": bool(lane["resolve_conversations"]),
        "allow_force_pushes": False,
        "allow_deletions": False,
    }
    if not 0 <= lane["approvals"] <= 6:
        raise ValueError("Invalid required approval count")
    return repo, branch, payload


def github_api(path: str, method: str = "GET", body: dict | None = None) -> dict:
    """Use the human's GitHub CLI identity; never read tokens into the script."""
    args = [
        "gh", "api", "-H", "Accept: application/vnd.github+json",
        "-H", f"X-GitHub-Api-Version: {API_VERSION}",
        "--method", method, path,
    ]
    if body is not None:
        args += ["--input", "-"]
    result = subprocess.run(
        args,
        input=json.dumps(body) if body is not None else None,
        text=True,
        capture_output=True,
        check=False,
    )
    if result.returncode != 0:
        raise RuntimeError(f"GitHub API {method} {path} failed: {result.stderr.strip()}")
    return json.loads(result.stdout)


def matches(existing: dict, payload: dict) -> bool:
    """Require the desired checks, review and mutation restrictions to be present."""
    checks = existing.get("required_status_checks") or {}
    reviews = existing.get("required_pull_request_reviews") or {}
    admin = existing.get("enforce_admins") or {}
    resolution = existing.get("required_conversation_resolution") or {}
    force = existing.get("allow_force_pushes") or {}
    deletion = existing.get("allow_deletions") or {}
    actual_checks = {check["context"] for check in checks.get("checks", [])} | set(checks.get("contexts", []))
    return (
        checks.get("strict") is payload["required_status_checks"]["strict"]
        and set(payload["required_status_checks"]["contexts"]).issubset(actual_checks)
        and admin.get("enabled") is payload["enforce_admins"]
        and (reviews.get("required_approving_review_count") or 0)
        >= payload["required_pull_request_reviews"]["required_approving_review_count"]
        and resolution.get("enabled") is payload["required_conversation_resolution"]
        and force.get("enabled") is False
        and deletion.get("enabled") is False
    )


def main() -> int:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--apply", action="store_true", help="Apply native protection (default: dry run)")
    parser.add_argument(
        "--replace", action="store_true",
        help="Allow replacement of an existing nonconforming branch-protection policy",
    )
    options = parser.parse_args()

    repo, branch, payload = declared_policy()
    print(f"Target: {repo}, branch {branch}; source: repo.dfconfig")
    if not options.apply:
        print("DRY RUN: native protection will be set to:")
        print(json.dumps(payload, indent=2))
        print("\nUse --apply with a GitHub CLI identity holding Administration:write.")
        return 0

    if not shutil.which("gh"):
        raise RuntimeError("GitHub CLI (gh) is required. Install it and run gh auth login.")
    branch_data = github_api(f"repos/{repo}/branches/{branch}")
    github_api(f"repos/{repo}/branches/development")  # Must exist before sealing main.
    endpoint = f"repos/{repo}/branches/{branch}/protection"
    if branch_data.get("protected"):
        existing = github_api(endpoint)
        if matches(existing, payload):
            print("Existing native branch protection satisfies the declared policy.")
            return 0
        if not options.replace:
            raise RuntimeError("Existing protection differs. Review manually; use --apply --replace only if overwriting is intended.")
    print("WARNING: Required review approvals are enforced even for the repository owner.")
    print("You cannot approve your own PR. A second reviewer or bot-authored release PR is needed.")
    github_api(endpoint, method="PUT", body=payload)
    after = github_api(f"repos/{repo}/branches/{branch}")
    if not after.get("protected") or not matches(github_api(endpoint), payload):
        raise RuntimeError("GitHub did not confirm the requested native protection.")
    print(f"VERIFIED: {repo}/{branch} is protected with required checks and reviews.")
    return 0


if __name__ == "__main__":
    try:
        sys.exit(main())
    except (RuntimeError, ValueError, KeyError, OSError) as error:
        print(f"error: {error}", file=sys.stderr)
        sys.exit(1)

def parse_source(file: Path, allow_plain_notes: bool) -> tuple[str | None, str]:
    """Read a source and its status; unmarked ordinary notes remain unpublished."""
    contents = file.read_text(encoding="utf-8").replace("\r\n", "\n")
    front = re.match(r"\A---\n(.*?)\n---\n", contents, flags=re.DOTALL)
    if not front:
        if allow_plain_notes:
            return None, ""
        raise ValueError(f"Missing YAML-style front matter: {file.relative_to(ROOT)}")
    status = re.search(r"(?m)^status:\s*([a-z_-]+)\s*$", front.group(1))
    if status is None:
        raise ValueError(f"Missing status field: {file.relative_to(ROOT)}")
    return status.group(1), contents[front.end():].strip()


def content_for(directory: str, required_status: str, heading: str) -> str:
    """Render a single projection from source records in stable filename order."""
    source = WORKSPACE / directory
    if not source.is_dir():
        raise ValueError(f"Missing canonical source directory: {source.relative_to(ROOT)}")
    parts = [f"# {heading}\n\n{HEADER}\n"]
    included = 0
    for file in sorted(source.glob("*.md")):
        status, body = parse_source(file, allow_plain_notes=directory == "notes")
        if status != required_status:
            continue
        if not body.startswith("# "):
            raise ValueError(f"Source must begin with a level-one heading: {file.relative_to(ROOT)}")
        # Convert source H1s to section headings in the generated document.
        body = re.sub(r"(?m)^(#{1,5})(?= )", lambda match: "#" + match.group(1), body)
        parts.append(f"\n{body}\n\n_Source: [{file.name}]({directory}/{file.name})_\n")
        included += 1
    if included == 0:
        raise ValueError(f"No {required_status} source records in {source.relative_to(ROOT)}")

#!/usr/bin/env python3
"""Compute an immutable release tag from Git tags, or opt-in VERSION file."""

from __future__ import annotations

import json
import re
import subprocess
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
TAG = re.compile(r"^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$")
VERSION = re.compile(r"^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$")


def parse_tag(tag: str) -> tuple[int, int, int] | None:
    match = TAG.fullmatch(tag)
    return tuple(map(int, match.groups())) if match else None


def choose_tag(
    mode: str,
    all_tags: list[str],
    head_tags: list[str],
    file_contents: str | None,
) -> str:
    """Resolve retries without moving a tag or reusing a tag on another commit."""
    if mode not in {"tags", "file"}:
        raise ValueError(f"Unsupported version mode: {mode}")
    if mode == "tags" and file_contents is not None:
        raise ValueError("Tag-only mode must not contain VERSION")
    if mode == "file" and (
        file_contents is None or not VERSION.fullmatch(file_contents.rstrip("\n")) or
        file_contents.count("\n") != 1 or not file_contents.endswith("\n")
    ):
        raise ValueError("File mode requires one strict major.minor.patch VERSION line")

    current = [tag for tag in head_tags if parse_tag(tag) is not None]
    if len(current) > 1:
        raise ValueError(f"Multiple SemVer tags on the release commit: {current}")
    if current:
        if mode == "file" and current[0] != f"v{file_contents.strip()}":
            raise ValueError(f"Current release tag disagrees with VERSION: {current[0]}")
        return current[0]

    parsed = [tag_version for tag in all_tags if (tag_version := parse_tag(tag)) is not None]
    if mode == "file":
        proposed = f"v{file_contents.strip()}"
        if parsed and parse_tag(proposed) <= max(parsed):
            raise ValueError(f"VERSION {proposed} does not exceed existing SemVer tags")
        return proposed

    if not parsed:
        return "v0.1.0"
    major, minor, patch = max(parsed)
    return f"v{major}.{minor}.{patch + 1}"


def git_lines(*args: str) -> list[str]:
    output = subprocess.run(
        ["git", *args], cwd=ROOT, capture_output=True, text=True, check=True
    )
    return [line.strip() for line in output.stdout.splitlines() if line.strip()]


def main() -> int:
    config = json.loads((ROOT / "repo.dfconfig").read_text(encoding="utf-8"))
    mode = config["repo"].get("versioning", {}).get("mode", "tags")
    version = ROOT / "VERSION"
    contents = version.read_text(encoding="utf-8") if version.is_file() else None
    tag = choose_tag(mode, git_lines("tag", "--list"), git_lines("tag", "--points-at", "HEAD"), contents)
    print(tag)
    return 0


if __name__ == "__main__":

              core.info('Tag-only mode: no VERSION file or PR bump is required.');
              return;

            if (pr.head.repo.full_name !== context.repo.owner + '/' + context.repo.repo) {
              core.notice('Fork PR: cannot write to its head; update VERSION manually.');
              return;

              core.notice('PR violates main source policy; do not mutate its branch.');
              return;

                owner, repo, workflow_id: 'docs.yml', ref: pr.head.ref,
              });
              if (pr.base.ref === 'main') {
                await github.rest.actions.createWorkflowDispatch({
                  owner, repo, workflow_id: 'main-source.yml',
                  ref: pr.head.ref, inputs: {pr_number: String(pr.number)},
                });
              }
            };
            const commits = await github.paginate(github.rest.pulls.listCommits, {
              owner, repo, pull_number: pr.number, per_page: 100
            });
            if (commits.some(c => c.commit.message.split('\n')[0] === marker)) {
              core.info('This PR was already bumped; reconcile checks on the current head.');
              await dispatchChecks();
              return;
            }

              const {data} = await github.rest.repos.getContent({owner, repo, path: 'VERSION', ref});
              if (!('content' in data)) throw new Error('VERSION is not a file');

              return 0;
            };
            const next = [...(compare(base, candidate) > 0 ? base : candidate)];
